## D209 The subagent runtime's limits come from omp, not Pi

What: the subagent runtime carries omp's default limits and caps, which have no Pi
counterpart: `MaxConcurrency` 32, `MaxDepth` 2, `DefaultAgentIdleTTL` 7 minutes, the
wait tool's 300-second default and 30-minute cap, and the output caps 500,000 bytes
inline and 5,000 characters in a summary. A caller overrides each through the runner
or the tool's arguments.

Why: Pi has no subagents, so there is no Pi value to mirror. These are omp's documented
defaults, kept identical so a delegation behaves the way it does in omp.

Scope: the subagent runtime only. No ported Pi code reads these values.

Owner decision: 2026-10-29, required by the fork's objective (a Go port of omp's
subagent runtime).

Call-site markers: `coding/subagent/spawn.go`, `coding/subagent_session.go`,
`coding/subagent_tool.go`.

Evidence: `TestSubagentConcurrencyBound`, `TestAgentDefinitionDepthCap` and
`TestIdleTTLParkingReleasesASession` exercise the concurrency, depth and idle limits;
`TestWaitToolReturnsASettlement` exercises the wait timeout.

Parity allowance: no paired Pi scenario spawns a subagent, so none observes these
values.

Remove when: the runtime's limits stop tracking omp's defaults.
